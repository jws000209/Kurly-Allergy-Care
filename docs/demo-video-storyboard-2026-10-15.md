## 3. 화면 전환·강조 규칙

### 화면 배치

- 원본 녹화는 **1920×1080, 16:9, 30fps**로 통일한다.
- 전체 화면은 서비스 소개, 실제 장바구니 확인, 마무리에 사용한다.
- 프로필 입력·판정·대화는 **패널을 크롭해 확대**한다. 패널 전체를 무조건 맞추기보다 현재 읽어야 할 영역을 중심으로 잡는다.
- 긴 추천 목록은 5개를 한 화면에 작게 욱여넣지 않고, 상단 답변을 읽힌 뒤 천천히 스크롤한다.
- 입력 문장과 결과는 같은 컷 안에서 연결한다. 결과부터 보여주고 입력을 나중에 설명하지 않는다.

### 확대와 전환

- 확대·축소: **0.25~0.35초**.
- 입력 전후와 수정 전후: 같은 위치에서 단순 컷 전환.
- 다른 장보기로 넘어갈 때만 **‘새 장보기’ 편집 자막**을 짧게 표시한다.
- 실제 새 대화 버튼 클릭도 보여줘, 이전 조건이 그대로 이어진 것처럼 보이지 않게 한다.
- 대기 시간을 잘랐다면 **‘응답 대기 구간 생략’**을 1초 정도 표시한다.
- 확대, 화살표, 테두리를 한꺼번에 쓰지 않는다. 한 화면에는 강조 대상 하나를 원칙으로 한다.

### 색과 글자

| 용도 | 권장 규칙 |
|---|---|
| 서비스·GPT 역할 | 보라색 `#6D28D9` |
| Rule Engine 역할 | 청록색 `#0F766E` |
| PASS 강조 | 초록색 `#15803D` |

색만으로 상태를 설명하지 않고 **PASS / BLOCK / 정보 확인 필요** 글자를 반드시 함께 보여준다.

내레이션 자막은 하단 중앙을 기본으로 하되, 입력창이나 담기 버튼을 가리면 해당 컷에서는 상단으로 옮긴다.

### 구현과 화면 표현을 맞추는 기준

- PASS를 ‘누구에게나 안전’으로 바꾸지 않는다. **‘등록한 회피 성분 미검출’**로 설명한다.
- 현재 추천 카드에는 GPT의 선택 이유가 직접 표시되지 않으므로, 가상의 설명 말풍선을 추가하지 않는다.
- 합계 금액을 편집으로 넣는다면 **‘추천 목록 합계 · 편집 표시’**라고 구분하고 실제 가격·최소 구매 수량으로 계산한다.
- 담기 직전 검증은 설명 자막으로 전달한다. 서비스에 없는 ‘검증 완료’ 팝업을 만들지 않는다.
- 최종 재검증에서 탈락한 상품의 이름이나 사유가 답변에 나타난 테이크는 사용하지 않는다. 단순히 강조를 빼는 것으로는 부족하다.

## 4. 녹화 전 준비 체크리스트

### 가상 계정·가족

| 항목 | 시연 설정 |
|---|---|
| 계정 | 개인 정보가 드러나지 않는 시연 계정 |
| 하늘 | 아들 / 첫째 / 우유 회피 / 엄격 모드 OFF |
| 바다 | 딸 / 둘째 / 알류 회피 / 엄격 모드 ON |
| 도윤 | 아빠 / 땅콩 회피 / 엄격 모드 OFF |

이 구성은 시작안이다. 원하는 결과가 실제로 나오는지 리허설한 뒤 확정한다. 결과를 맞추기 위해 녹화 화면의 프로필과 실제 적용 조건을 다르게 두면 안 된다. 바다의 엄격 모드는 4번 컷에서 OFF에서 ON으로 바꾸고, 이후에는 표의 설정을 유지한다.

- [ ] 하늘 등록 장면을 녹화하기 전에는 바다·도윤만 준비해 둔다.
- [ ] 9번 컷에는 자녀 프로필이 둘 다 존재하고, 선택 프로필은 해제돼 있어야 한다.
- [ ] 컬리 계정 이름, 배송지, 연락처, 주문 내역, 브라우저 자동완성·알림이 보이지 않게 준비한다.

### 입력 순서

1. 새 대화, 선택 프로필 해제 → `아이 간식 추천해줘`
2. 같은 대화 → `첫째 간식 2만원 이내 5개`
3. 같은 대화 → `2번 상품 빼줘`
4. 같은 대화 → `더 저렴하게`
5. 새 대화 → `아빠랑 소풍 점심 2만원 이내 3개 추천해줘`
6. 새 대화 → `아빠 만두 2개 추천해줘`
7. 같은 대화 → `만두 대신 라면`
8. 최신 추천 카드 → `장바구니에 추가`
9. 성공 안내 → `장바구니 보기`

### 서버·확장·상품

- [ ] 기존 8000 포트 사용 여부를 확인하고, 시연할 백엔드와 확장이 같은 서버를 바라보는지 확인한다.
- [ ] `/api/health` 정상 응답, 상품 적재, 확장 패널의 프로필 목록 로딩을 확인한다.
- [ ] 확장을 다시 로드한 뒤 컬리 페이지도 새로고침한다.
- [ ] GPT 설정뿐 아니라 **실제 요청 해석과 상품 선택에 사용된 모델**을 확인한다. 모델 설정값만으로 성공을 판단하지 않는다.
- [ ] PASS / BLOCK / 정보 확인 필요 상품 URL을 각각 확보하고, 실제 페이지에서 판정되는지 확인한다.
- [ ] 담을 상품은 판매 중이고 품절·옵션 선택 문제가 없는 상품으로 준비한다.
- [ ] 시연 장바구니의 시작 상태를 기록한다. 가능하면 전용 계정의 빈 장바구니에서 시작한다.
- [ ] 실제 담기까지 리허설한다. 자동 테스트 통과만으로 실사이트 동작을 확인했다고 보지 않는다.
- [ ] 같은 문장·같은 순서로 최소 2회 리허설하고, 추천 개수·가격·교체 성공 여부를 기록한다.

### 리허설 합격 기준

- ‘아이’ 요청에서 새 추천 없이 실제 확인 질문이 나온다.
- 첫째 요청에서 대상과 예산이 맞고, 5개를 확보할 수 있는지 확인된다.
- 삭제 후 최신 추천 목록에서 해당 상품이 빠진다.
- 가격 변경 장면에서 실제로 더 싼 대안이 확인된다.
- 종류 변경은 **소풍 대화와 분리된 새 대화**에서 성공한다. 현재 소풍 조건은 라면을 제외한다.
- 최신 카드로 실제 담기에 성공하고, 컬리 장바구니에서 같은 상품이 확인된다.
- 최종 재검증 탈락 상품의 이름·사유가 영상에 없다.
