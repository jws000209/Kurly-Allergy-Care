# 알레르기 규칙 재점검 (2026-10-14)

후속 상태: 아래 개선안을 구현했습니다. 공통 문맥 모듈·한영 예외·원재료 유효성 검사·테스트 격리·friendly 답변 옵션을 적용한 전체 테스트는 113개 통과했습니다. 아래 내용은 수정 전 재현 기록입니다.

코드와 현재 한영통합 XLSX를 읽고 순수 함수로 재현했습니다. 외부 API를 호출하거나 DB를 초기화·변경하지 않았습니다. 이번 점검에서는 판정 코드를 수정하지 않았습니다.

## 확인된 정상 동작

- XLSX의 자동 확정 대상 1,231개 항목 각각을 검색했을 때 해당 알레르겐 누락 0개. 이는 사전 검색 검증이며 실제 OCR·판정 정확도 검증은 아닙니다.
- 캐슈밀크/soy milk는 우유로 자동 연결하지 않음. 별도 milk가 있으면 검출하는 기본 사례는 통과.
- 레시틴, 모호한 크림, 콜라겐, 포괄적 nuts/fish는 관련 회피 조건에서 검토 대상으로 처리.
- 한국어 혼입 문구 분리, 엄격 모드 차단, 공식 표시의 확장 20종 근거 제한, 사전/모델 실패 시 UNVERIFIED 유지.

## 재현된 문제

| 항목 | 재현 입력 / 회피 조건 | 현재 결과 | 권장 처리 |
|---|---|---|---|
| 원재료 유효성 | ingredients=`원재료 정보 없음`, 회피=우유 | verified=True. 가짜 GPT가 PASS를 반환하면 최종 PASS | 정보 없음·N/A·표시 참조 등은 판정 근거로 인정하지 않고 UNVERIFIED |
| 영어 예외 검색 | ingredients=`rice, starch`, 회피=밀 | E007 미검색. 가짜 GPT가 PASS를 반환하면 최종 PASS | starch/modified starch를 E007 검토 규칙과 연결해 원료 확인 |
| 부정 표시 범위 | ingredients=`milk-free, milk` 또는 `우유 함유 없음, 우유`, 회피=우유 | contains=[] / UNVERIFIED | 별도 긍정 성분은 남겨 BLOCK. 부정문은 해당 출현 구간만 처리 |
| 영어 혼입 문구 | ingredients=`rice`, label=`May contain milk` 또는 `Made in a facility that processes milk`, 회피=우유, strict=False | contains=[우유], cross=[] / BLOCK | cross로 분리. 일반 모드는 경고와 최종 검토, 엄격 모드는 BLOCK |
| 부정 표현 누락 | `without milk`, `no added milk`, `milk is not contained`, `우유 함유 아님`, `우유는 함유하지 않음` | 우유 함유로 BLOCK | 부정 범위를 인식해 추가 확인. 부정 문구만으로 PASS를 보장하지 않음 |
| 향/맛 문맥 불일치 | `milk flavor`와 `milk chocolate flavor` | 우유 함유로 BLOCK. 한국어 향/맛은 필터 존재 | 언어별 문맥 정책 통일. 향료의 원료를 추정하지 않고 근거 부족 시 UNVERIFIED |

가짜 GPT의 PASS는 코드 보호 규칙의 빈틈을 확인하기 위한 입력입니다. 실제 Luna가 해당 답을 반환했다는 뜻은 아닙니다.

## 권장 보완 순서

1. 원재료 유효성 게이트와 한영 예외 표현 연결: 근거 부족이 최종 PASS가 될 수 있는 경로부터 보완.
2. 출현 구간별 긍정·부정·혼입 분류: 정규화 문자열 전체의 부정 표시가 다른 긍정 출현까지 가리지 않도록 변경.
3. 영어 향/맛·혼입·부정 표현을 동일 정책으로 처리하고 원문 구간·출처를 근거에 보존.
4. 혼합 문장, 정보 없음/OCR 안내문, 영어 예외를 회귀 평가 세트에 추가. 전체 pytest 실행 전 시험 DB/시드/대화 상태 격리를 적용해야 함.

## 앞선 테스트 결과 정정

전체 실행의 실패 2건은 테스트 환경변수보다 앱 모듈이 먼저 로딩되어 실제 `backend/data/kac.sqlite3`와 상품 시드를 사용한 것이 원인입니다. 실제 DB에서 테스트용 첫째 아들·아빠 중복 프로필과 만두 상품을 확인했습니다. 단독 실행은 2/2 통과했고, 메모리에서 테스트별 DB·시드·대화 상태를 격리한 전체 실행은 87/87 통과했습니다. 격리 fixture를 파일에 적용하거나 기존 테스트 데이터를 삭제하지는 않았습니다.
